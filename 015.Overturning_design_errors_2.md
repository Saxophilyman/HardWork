Подсистема разделена на 4 условные логические части, которые для импорта идут сверху вниз, а для экспорта наоборот:
1) Приём данных через HTTP или Batch(entry)
2) Преобразователи JSON/CSV в документ(format)
3) Сами документы с данными(document)
4) Прикладные сценарии для импорта/экспорта по Guid/id(application)
Каждая из этих частей отвечает за свою часть логики. Части не знают "лишнего".
Все имеющиеся сценарии получаются сохранёнными, однако HTTP и batch используют один импорт, CSV больше не залезает напрямую в БД, исправлен ответ при ошибке импорта, добавлены исключения.

```java
@Service
@RequiredArgsConstructor
public class RegisterVehicleMovementService
        implements RegisterVehicleMovementUseCase {

    private final VehicleLookupPort vehicleLookupPort;
    private final TripPeriodStore tripPeriodStore;
    private final TelemetryStore telemetryStore;

    @Override
    @Transactional
    public Long execute(RegisterVehicleMovementCommand command) {
        VehicleRef vehicle = vehicleLookupPort.requireById(command.vehicleId());

        TripPeriod period = command.tripPeriod();

        validateTelemetryInsidePeriod(command.telemetry(), period);

        if (tripPeriodStore.overlaps(vehicle, period)) {
            throw new IllegalArgumentException("Период пересекается с существующей поездкой");
        }

        Long tripId = tripPeriodStore.save(vehicle, period);

        telemetryStore.append(vehicle, command.telemetry());

        return tripId;
    }
}
```
