По итогу я пришёл к следующему варианту.   
Подсистема разделена на 4 условные логические части, которые для импорта идут сверху вниз, а для экспорта наоборот:
1) Приём данных через HTTP или Batch(entry)
2) Преобразователи JSON/CSV в документ(format)
3) Сами документы с данными(document)
4) Прикладные сценарии для импорта/экспорта по Guid/id(application)
Каждая из этих частей отвечает за свою часть логики. Части не знают "лишнего".
Все имеющиеся сценарии получаются сохранёнными, однако HTTP и batch используют один импорт, CSV больше не залезает напрямую в БД, исправлен ответ при ошибке импорта, добавлены исключения.

```java
@Component
@RequiredArgsConstructor
public class VehicleByGuidDocumentIO {
    private final ObjectMapper objectMapper;
    private final CsvVehicleByGuidReader csvReader;
    private final CsvVehicleByGuidWriter csvWriter;

    public VehicleExportDtoByGuid read(DataFormat format, InputStream input) throws IOException {
        return switch (format) {
            case JSON -> objectMapper.readValue(input, VehicleExportDtoByGuid.class);
            case CSV -> csvReader.read(input);
        };
    }

    public void write(DataFormat format, VehicleExportDtoByGuid document, OutputStream output) throws IOException {
        switch (format) {
            case JSON -> objectMapper.writeValue(output, document);
            case CSV -> csvWriter.write(document, output);
        }
    }
}
```
