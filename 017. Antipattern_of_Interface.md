Говоря о ненужных состояниях внутренних вычислений можно также рассмотреть и следующий пример

```java
    protected void doFilterInternal(HttpServletRequest request,
```

По сути всё что нам нужно это 2 состояния: валидный или не валидный Bearer. Однако в коде имеется разные логические сочетания
Они зависят от двух значений, которые определяют наличие токена:
```java
String jwt = null;
String username = null;
```
И даже если в логике метода они не противоречат между собой, то всё равно являются взаимозависимыми, определяя условия, что если username существует,
то jwt уже должен существовать и соответствовать этому username. А null используется к качестве внутренних стадий вычислений.

Можно сделать более явное прохождение токена.  
В результате null не будет использоваться как скрытое значение алгоритма, а значения jwt и username будут создаваться только после прохождения проверки и в том, месте, где непосредственно будут использоваться.

```java
@Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        authenticateIfPossible(request);
        filterChain.doFilter(request, response);
    }

    private void authenticateIfPossible(HttpServletRequest request) {
        String authorizationHeader =request.getHeader("Authorization");

        if (authorizationHeader == null || !authorizationHeader.startsWith("Bearer ")) {
            return;
        }

        if (SecurityContextHolder.getContext().getAuthentication() != null) {
            return;
        }

        String jwt = authorizationHeader.substring(7);
        String username = jwtUtil.extractUsername(jwt);

        if (username == null) {
            return;
        }

        UserDetails userDetails =generalDetailsService.loadUserByUsername(username);

        if (!jwtUtil.isTokenValid(jwt, userDetails.getUsername())) {
            return;
        }

        UsernamePasswordAuthenticationToken authentication = new UsernamePasswordAuthenticationToken(userDetails,null, userDetails.getAuthorities());

        authentication.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));

        SecurityContextHolder.getContext().setAuthentication(authentication);
    }
```

```java
        return TrackResponse.geoJson(GeoJsonConverter.convertToGeoJSON(dtoPoints));
    }

    return TrackResponse.json(dtoPoints);
}
```
Работу со входящей строкой можно также перенести на границу контроллера и перед вызовом сервиса преобразовывать в TrackFormat.
Теперь получится, что большинство неправильных сочетаний и неоднозначностей, которые раньше были допустимы для компилятора, невозможно создать через публичный интерфейс класса.
