Пример 1  
Пресловутый бренд автомобиля при создании нового vehicle. В ДТО он является вложенным и на нём может быть null. А при заполнении по сути только нужен его id и он обязателен

Было
```java
@Data
public class VehicleDTO {
    @NotEmpty(message = "Обязательное поле")
    private String vehicleName;

    @NotEmpty(message = "Госномер обязателен")
    private String licensePlate;

    private BrandDTO brand;
}
```

```java
@PostMapping("/enterprises/{enterpriseId}/vehicles")
public ResponseEntity<Void> createVehicle(@CurrentManagerId Long managerId,
                                          @PathVariable Long enterpriseId,
                                          @RequestBody @Valid VehicleDTO vehicleDTO,
                                          BindingResult bindingResult) {
    ValidationBindingUtil.Binding(bindingResult);

    Enterprise enterprise = enterpriseService.findEnterpriseForManager(managerId, enterpriseId);

    Vehicle vehicle = vehicleMapper.convertToVehicle(vehicleDTO, enterprise.getTimeZone());

    vehicle.setEnterpriseOwnerOfVehicle(enterprise);

    Long brandId = getBrandIdOrThrow(vehicleDTO);

    vehicleService.save(vehicle, brandId);

    return ResponseEntity.status(HttpStatus.CREATED).build();
}
```

```java
//сама проверка по бренду
private Long getBrandIdOrThrow(VehicleDTO dto) {
    if (dto.getBrand() == null || dto.getBrand().getBrandId() == null) {
        throw new IllegalArgumentException("Не указан бренд автомобиля");
    }
    return dto.getBrand().getBrandId();
}

```
Стало  
Можно попробовать сделать специальный класс именно для метода post, которыйй будет сразу закрывать эти два вопроса

                                          @PathVariable Long enterpriseId,
                                          @RequestBody @Valid VehicleWriteRequest request,

Пример 2  

Неожиданно для себя обнаружил подобный случай в DriverDTO и его конвертации  
Было
```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class DriverDTO {
    private Long driverId;

    @NotEmpty(message = "Обязательное поле")
    private String name;

    @NotEmpty(message = "Обязательное поле")
    private String salary;

    private EnterpriseDTO enterprise;

    private boolean isActive;

    private VehicleDTOForDriver activeVehicle;
}
```
Зарплата представлена типом строки и в маппере приходится делать соответствующие проверки
```java
public Driver toEntity(DriverDTO dto, Enterprise enterprise) {
    if (dto == null) {
        throw new IllegalArgumentException("DriverDTO cannot be null");
    }

    Driver driver = new Driver();

    driver.setDriverId(dto.getDriverId());
    driver.setDriverName(dto.getName());
    driver.setDriverSalary(parseSalary(dto.getSalary()));
    driver.setActive(dto.isActive());
    driver.setEnterpriseOwnerOfDriver(enterprise);

    return driver;
}
```
Сам метод "страховки"
```java
private int parseSalary(String salaryStr) {
    if (salaryStr == null || salaryStr.isBlank()) {
        // @NotEmpty в DTO уже проверит пустоту, но на всякий случай:
        throw new IllegalArgumentException("Зарплата не может быть пустой");
    }

    try {
        return Integer.parseInt(salaryStr.trim());
    } catch (NumberFormatException e) {
        throw new IllegalArgumentException("Некорректное значение зарплаты: " + salaryStr);
    }
}
```
Стало  
Можно пойти аналогичным первому варианту путём и для создания и изменения использовать отдельный рекорд, который позволит использовать сразу корректный для ввода вариант типа.  
Но с другой стороны, можно вообще уйти от типа String и использовать сразу в изначальном DTO, а ещё лучше сущности Integer или более подходящий тип для зарплаты.  
Но не будет ли это переусложнением исходя из контекста "текущей необходимости"?  
Я выбрал первый вариант, т.к. реальная зарплата особо сильно в проекте не используется и не влияет на расчёты и фунекциональность.  
В итоге
```java
public record DriverWriteRequest(
        @NotBlank(message = "Имя водителя обязательно")
        String name,

        @NotNull(message = "Зарплата обязательна")
        @PositiveOrZero(message = "Зарплата не может быть отрицательной")
        Integer salary,

        boolean active
) { }
```
```java
@PostMapping("/enterprises/{enterpriseId}/drivers")
public ResponseEntity<Void> createDriver(@CurrentManagerId Long managerId,
                                         @PathVariable Long enterpriseId,
                                         @RequestBody @Valid DriverWriteRequest request,
                                         BindingResult bindingResult) {
    ValidationBindingUtil.Binding(bindingResult);

    Enterprise enterprise = enterpriseService.findEnterpriseForManager(managerId, enterpriseId);

    Driver driver = driverMapper.toEntity(request, enterprise);

    driverService.save(driver);

    return ResponseEntity.status(HttpStatus.CREATED).build();
}
```
```java
public Driver toEntity(DriverWriteRequest request, Enterprise enterprise) {
    Driver driver = new Driver();

    driver.setDriverName(request.name());
    driver.setDriverSalary(request.salary());
    driver.setActive(request.active());
    driver.setEnterpriseOwnerOfDriver(enterprise);

    return driver;
}
```
Таким образом  мы избегаем излишних проверок на корректность получаемых данных
